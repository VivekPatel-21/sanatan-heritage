# Future development roadmap — proposals requiring scope approval

No item here authorizes website changes. The recommended opening task is read-only review followed by a concrete proposal.

## 1. Confirm the migration baseline

Open the extracted project, install locked dependencies, rebuild and run lint/check/test. Confirm remote branch state before any push. Review all 14 rendered pages on mobile, tablet and desktop, both themes, keyboard navigation, reduced motion and 200% zoom. Check hero alignment, caption wrapping, glossary light-mode contrast, search/menu focus and scroll behaviour. Report bugs separately from optional redesign ideas.

Acceptance: reproducible build and documented visual evidence; no content or approved styling changed during the audit.

## 2. Complete the next narrative, after approval

Recommended next story: **Hanuman's journey to Lanka**, based on Ramayana, Sundara Kanda. Agree chapter scope and source edition first: crossing the ocean, search for Sita, Ashoka Vatika, message and return. Use the owner's Ramayana editions and source links with accurate chapter references. Create new unique reader artwork rather than duplicating its collection card. Then consider Krishna and Govardhana.

Acceptance: original source-faithful English retelling, clear variant notes where necessary, source line/entry, characters, reading time, chapters, navigation and reviewed iconography; existing stories remain unchanged.

## 3. Strengthen discovery and collection coherence

Review how reading paths behave when a destination is still only a preview. Propose sensible connections among deity, scripture, glossary and story pages without promising unavailable readers. Check metadata for the eventual host and confirm private/public indexing policy. Audit CSS cascade incrementally if it causes real layout problems.

## 4. Expand formats selectively

Prioritise with the owner: Hindi first and Gujarati optionally; audio; short family retellings/print cards. Translation needs fluent review, script font coverage, route/language metadata and preservation of Sanskrit terms. Audio requires pronunciation review and permission for voices/music; offer a text transcript. Family adaptation must stay source-faithful and distinct from the complete retelling.

## 5. Add researched connections

Festival/tithi explanations connected to stories; a carefully sourced places map. Agree calendar convention, observer location/timezone and reliability before publishing date-sensitive data. Verify temple identity and geography, and provide text alternatives to a map. Newsletter needs a separate approved service/consent/privacy scope.

## Outstanding dependencies

Rendered QA remains uncompleted. Exact temple identities and rights for supplied visual material are unconfirmed. A complete original conversation export and an identifiable Skanda Purana upload are unavailable. The two Archive.org Bhagavata volumes are links, not recovered local PDFs. Future features require source, assets and scope decisions; no schedule has been promised.
